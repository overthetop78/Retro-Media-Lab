References locales : Gens cpu_sh2.c MSH2_Init/SSH2_Init mappe P0/P1 ROM, SDRAM et cache-RAM directement ; PicoDrive pico/32x/memory.c sh2_write16_rom decrit le cout du cache et son correctif WWF Raw. Le nouveau choix est une politique hote explicite, Cached reste la valeur initiale et aucun choix de machine n'est change par defaut.

En DirectMapped, P0/P1 externes ne consultent plus FindLine et ne remplissent/modifient plus les lignes cache. CodeVersion/CodeEpoch proviennent du bus externe ; C0 garde ses versions et son contenu. En P0 seulement, la lecture d'instruction active CCR&3==1 et la lecture de donnees active CCR&5==1 prennent la latence de hit zero ; sinon les attentes externes restent appliquees. P1 garde toujours les attentes externes existantes, sans biais de changement de cycles P1. Les attentes d'ecriture restent celles du bus. Les fonctions IO, WDT/FRT/DMA, purge, tableaux d'adresses et format de contexte restent presents.

Changer MemoryMode invalide les blocs compiles et les plages de fetch hote, sans avancer les horloges ni changer les registres sauvegardes. En DirectMapped, un changement des deux bits de controle du cache code invalide aussi les blocs dont le budget de fetch etait compile ; une purge CCR sans changement de ces bits ne provoque pas une recompilation generale. Le besoin equivalent de mise a jour des budgets HardwareCached est transmis a l'agent du coeur, sans modifier sa logique WordVersion.

Limite explicite : les jeux qui utilisent des ecritures cachees dans une zone ROM (exemple WWF Raw des sources PicoDrive) ne sont pas declares compatibles dans DirectMapped. Aucun ROM shadow ni correctif de jeu n'est invente ici. Aucun build/test lance par cet agent, aucun gain FPS presume ; le parent compare les routes sur les ROM.

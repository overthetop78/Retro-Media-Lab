# Uniformisation des modules et exemple commenté

Le résultat attendu est un RetroMediaLab.Emulation.Example complet, autonome et commenté dans ses fichiers C#, utilisant la même structure et les mêmes raccordements au SDK que les 23 modules existants. Toute fonctionnalité utilisée dans une famille doit être intégrée au socle et raccordée dans les autres modules ; le mock ne doit pas être le seul à la montrer. Seules les implémentations sans usage réel dans tout le projet peuvent disparaître. Les comportements et configurations existants doivent être conservés. Sur demande explicite, les anciens formats de sauvegardes d’état sont abandonnés au profit du seul format commun ; aucun lecteur de compatibilité ne doit être réintroduit.

Ce fichier contient des modifications de code. La documentation pédagogique sera dans les commentaires des sources Example, sans guide Markdown séparé. Les cases ouvertes ci-dessous ne constituent pas des corrections déjà réalisées.

État vérifié avant modification : les 23 projets ciblent net10.0 et référencent RetroMediaLab.Emulation. Leurs machines appellent StartThread, WaitForStartOrStopAsync, RunCore et DisposeMachineAsync du SDK. L’audio reste réparti entre 16 contrôleurs partagés et 7 sorties locales : Amstrad, Commodore, Microsoft, NEC, Nintendo, Sega et Sony. Les interfaces locales IEmulatorAdapter ne sont pas encore identiques : Acorn expose GetRuntimeOptions, Sony et Microsoft ne le déclarent pas, alors que la fabrique Sony l’implémente déjà. Le modèle sdk/module-template ne contient qu’une fabrique qui lève NotImplementedException. Les fonctions communes utiles sont actuellement internal et accessibles aux seuls amis déclarés : cela doit être résolu pour qu’un nouveau module réutilise effectivement le socle.

## Contrat d’adaptateur commun aux modules indépendants

Les échanges module–SDK passent par des interfaces publiques. Les classes de fonctions et de services qui implémentent ces contrats restent internes : aucune autorisation amie de production ni ouverture générale des helpers ne constitue le résultat attendu. Les lignes cochées d’ouverture ci-dessous décrivent une étape antérieure ; elles ne prouvent pas ce raccordement final. Le diagnostic est le premier service raccordé à cette API, sans recopier ses algorithmes.

## Supprimer la dépendance restante aux assemblies amis

Les références de types des 23 DLL compilées montrent encore 39 types SDK internes consommés par les modules. Ce relevé ne couvre pas les constantes incorporées dans les DLL ni les membres internes de classes déjà publiques : ces usages doivent aussi être résolus avant de retirer les autorisations. Les changements suivants doivent conserver les corps et n’ouvrir que les contrats et opérations utiles aux auteurs de modules, avec leurs commentaires de propriété, d’erreur et de destruction.

# NEC µPD765A / µPD765B / µPD72065B

## État de la reprise

Reprise fonctionnelle et validation terminées après le WD1770/1772 ; livraison Debug avec les 24 modules construite et vérifiée. Le composant reçoit les broches et ne possède aucune image. Les limites documentaires PS/veille et le placement numérique du polling sont décrits explicitement ci-dessous ; les anciennes suites sectorielles ne constituent pas la preuve de cette reprise.

Le code actuel se trouve dans `Controllers/NEC/UPD765/UPD765/`. `Upd765` possède les phases commande/exécution/résultat et `Upd765DriveControl` les déplacements et causes d'interruption. Aucun propriétaire de machine Acorn n'instancie ces classes dans l'état examiné ; `ChipUsings.cs` importe seulement leurs namespaces. Ce constat décrit le raccordement actuel, pas l'utilité ni la destination du composant.

Le cœur est destiné notamment au 82C711 des A3010/A3020/A4000 : la [fiche Chips and Technologies, section 5.1](https://www.chiark.greenend.org.uk/~theom/riscos/docs/82c711.pdf), décrit un FDC compatible NEC µPD72065B intégré avec un séparateur de données. Le [manuel technique Acorn de ces machines](https://classicacorn.computinghistory.org.uk/32bit_service_manuals/A3020trm.pdf), section 1-8, confirme le contrôleur de la famille 765. Le [manuel Risc PC](https://wiki.gen.net.uk/lib/exe/fetch.php/archive/computers/acorn/systems/acorn-risc-pc-technical-reference.pdf) décrit également le cœur 765 du FDC37C665. Le cœur réutilisable reste dans Chips ; les registres supplémentaires, le séparateur et les particularités de chaque Super I/O doivent être reproduits dans le composant correspondant, puis raccordés aux autres puces par la machine. Les autres modules de machines compatibles peuvent réutiliser ces composants.

Tant qu'aucune de ces cartes natives n'est raccordée, une preuve invitée utilisant un périphérique de banc doit l'identifier explicitement et ne pas le présenter comme une carte Acorn d'origine.

## Écarts constatés dans l'implémentation initiale

| Domaine | Code existant et écart établi |
|---|---|
| Frontière du composant | Le constructeur reçoit `IDiskImage`, la position physique et des callbacks mécaniques. Les services lisent, écrivent et formatent des secteurs directement. Le composant doit traiter les broches et laisser les images et lecteurs à leur propriétaire. |
| Bus CPU/DMA | Les méthodes atomiques FIFO/DMA existent, mais CS/RD/WR/A0/DACK, bus haute impédance et reset maintenu ne sont pas exposés. Les acquittements de fin de strobe ne peuvent pas être exercés. |
| Reset | `Upd765DriveControl.Reset` remplace SRT/HUT/HLT par les valeurs initiales. NEC 5-5 indique que RESET ne modifie pas ces trois paramètres. L'interruption après reset avec READY haut n'est pas reproduite. |
| Variantes | L'enum ne propose que 765A et 72065B. NEC distingue aussi le 765B : VERSION 90, overrun du dernier octet et relâchement DRQ autonome à l'entrée en résultat. Le code ne distingue pas ces deux derniers comportements. |
| Horloges série | La cadence est calculée depuis `DataRate` et le bit MFM. WCLK, WINDOW et RDATA ne sont pas des entrées. La fiche précise que le PLL est externe et fournit WINDOW avec RDATA ; lui substituer un accès sectoriel n'est pas équivalent. |
| Signaux des lecteurs | Les pas sont des callbacks de déplacement, sans largeur STEP, multiplexage US0/US1, RW/SEEK, FLTR, LCT/DIR, HDLD ni présélection documentés. La rotation est inventée dans le contrôleur à cinq tours/s. |
| Lecture/écriture | La recherche parcourt les secteurs projetés de l'image ; il n'y a pas d'index d'entrée, de recherche des marques dans un flux reçu, de CRC calculé bit par bit ni de WDATA/WE produit. |
| Formatage | Les CHRN sont collectés puis `FormatTrack` est appelé sur l'image. Le flux FM/MFM, les gaps, les marques, la précompensation demandée et les interruptions de porte ne sont pas émis par la puce. |
| Tests | Les tests de transfert empruntent le faux disque des tests HD63463 et présupposent l'accès sectoriel. Ils doivent être rendus autonomes et remplacés par des scénarios de signaux pour prouver le composant complet. |

## Contrat numérique à vérifier

Les vérifications concernent toutes les combinaisons valides du bus CPU et DMA, les accès étirés, les acquittements uniques, le reset pendant un accès et le maintien du bus désactivé. Les façades atomiques restent utiles aux cartes qui ne représentent pas leurs strobes individuellement.

Le séquenceur doit couvrir Specify, Sense Drive Status, Sense Interrupt Status, Seek/Recalibrate simultanés, Read Data/Deleted/ID/Diagnostic, Write Data/Deleted, Format et les trois scans. La matrice doit distinguer DMA/non-DMA, TC avant/pendant/après le dernier octet, OR du dernier octet selon A/B, interruptions sans cause, causes concurrentes, changement READY, WPRT, faute lecteur, absence d'index, mauvaises marques/CHRN/CRC, SK/MT/EOT/DTL/STP et résultats complets ST0/ST1/ST2/CHRN.

Les broches à exercer comprennent RESET, CS/RD/WR/A0/DB, DACK/DRQ/TC/INT, CLK/WCLK/WINDOW/RDATA, INDEX/READY, FLT/TRK0, WPRT/2SIDE, US0/US1, SIDE, RW/SEEK, FLTR/STEP, LCT/DIR, HDLD, SYNC/MFM, PS0/PS1 et WDATA/WE. Les caractéristiques électriques analogiques ne doivent pas être inventées ; les événements numériques et délais nominaux documentés doivent être distingués de ces limites.

## Résultats

Le premier groupe de corrections ajoute le bus CS/RD/WR/A0/DACK avec haute impédance, accès étirés, écriture échantillonnée et lecture acquittée en fin de strobe ; RESET maintenu désactive le bus et les accès atomiques. SRT/HUT/HLT sont maintenant conservés pendant RESET. L'enum ajoute 765B sans renuméroter 765A/72065B, avec le résultat VERSION correspondant. Les différences OR/DRQ restent à réaliser.

Premier passage Debug : 78/79, avec une attente incorrecte dans le nouveau test de lecture étirée (0x90 au lieu de 0x50 lorsque RQM est bas et DIO haut). Après correction de cette attente, 79/79 réussites, zéro échec. La suite inclut les anciens scénarios sectoriels ; leur présence ne prouve pas la réception physique encore à raccorder. Aucun résultat invité, benchmark final ni clôture de cette puce n'est annoncé.

Le canal interne `Upd765ReadChannel` reçoit maintenant RDATA et les transitions WINDOW produites par le PLL externe. Comme indiqué par NEC 5-10, aucune polarité de WINDOW n'est imposée : les deux polarités permettent de retrouver l'alignement des marques. Les contrôles exercent les 256 octets FM/MFM, les 16 décalages initiaux, les marques ID/DATA/Deleted/Index, les trois A1/C2, les fausses synchronisations dans les données ordinaires, les horloges erronées, un RDATA maintenu sur plusieurs fenêtres et l'annulation par reset/changement de densité. Le registre CRC dispose de références CCITT/IBM, d'une vérification bit/octets et des erreurs unitaires de tous les bits d'un enregistrement.

Le groupe µPD765 donne désormais **112 réussites, zéro échec en Debug et en Release**. Ce canal et le CRC ne sont pas encore raccordés au séquenceur de commandes : les accès sectoriels du tableau initial restent à retirer dans cette même reprise avant clôture. Ces résultats ne sont donc pas présentés comme une validation complète du contrôleur.

Le polling READY est maintenant effectué tous les 8 192 cycles de CLK (1,024 ms à 8 MHz, 2,048 ms à 4 MHz), d'après la section Polling Feature de la fiche NEC. Le décompte conserve le reliquat lorsque l'horloge du propriétaire n'est pas un multiple de CLK. Un changement qui disparaît entre deux échantillons ne crée plus une interruption fictive. Le relâchement de la broche RESET arme un premier contrôle et signale les lecteurs READY ; le reset annule cet événement et les déplacements, y compris lorsqu'il est déclenché depuis le callback STEP. Le nouveau passage Debug donne **125/125 réussites**, incluant la cadence, quatre fréquences propriétaire, les causes des quatre unités, les avances par lots/par pas et l'absence de double cause après perte READY pendant Seek.

`Upd765WriteChannel` réalise le registre série piloté par WCLK externe : mots FM/MFM, horloges manquantes demandées explicitement par le séquenceur, WE/WDATA, frontières de mot, registre CRC mis à jour sur chaque bit DATA et coupure des fronts futurs au reset/retrait de porte. F5/F6/F7 restent des données ordinaires ; le 765 ne possède pas le protocole de jetons du WD1770. Le temps écoulé sur CLK sans front WCLK ne décale aucun mot.

Le délai numérique de sortie choisi est d'une demi-clock, soit 62,5 ns à 8 MHz : il se situe dans la plage tCD/tCWE de 20 à 100 ns publiée par NEC 5-8, mais la fiche ne fournit pas une valeur nominale exacte. WDATA suit ensuite la largeur haute du WCLK externe. Ce choix n'est pas présenté comme une mesure analogique. WDATA reste non précompensé ; le calcul des demandes PS0/PS1 et le décalage extérieur associé restent à examiner et raccorder avant clôture.

Le passage regroupé après ajout de la sortie série donne **146/146 réussites en Debug et 146/146 en Release**, zéro échec. Les nouveaux contrôles comprennent toutes les valeurs d'octet FM/MFM, les mots A1/C2/C7/D7, les fronts WCLK répétés/absents, le CRC partiel, le maintien du dernier front lors de la fermeture de porte, les files de mots et l'annulation à chacune des seize cellules. La première compilation du nouveau test a relevé une accessibilité incohérente de son paramètre enum interne ; le paramètre public du test est maintenant son identifiant numérique, sans exposer l'enum de la puce.

Le raccordement série a ensuite remplacé le chemin sectoriel. Le constructeur ne reçoit plus d'image ni de position physique ; `SetReadSignals`, `SetWriteClock` et `SetIndex` alimentent le composant. Les commandes lisent les CHRN et CRC réellement reçus, les recherches expirent sur deux index fournis par le lecteur, et un registre DATA unique assure le dialogue DMA/PIO. TC arrête les nouvelles demandes hôte tout en laissant finir le champ/CRC ; l'écriture remplit de zéros les octets restants. Le formatage émet les gaps, marques, CHRN fournis par le CPU, CRC et remplissage, puis attend le second index. Les impulsions déjà émises ne sont pas annulées par RESET.

Le banc `PinFixture` fournit un encodeur indépendant, WINDOW/RDATA, WCLK et index ; il capture les mots WDATA. Il ne dépend plus du faux disque HD63463 ni des bibliothèques d'images. Premier passage après raccordement : 135/137. Les deux attentes erronées du banc ont été corrigées : attendre RQM plutôt que le prochain événement quelconque pendant le polling READY, et chercher la marque DATA après l'ID plutôt que de confondre un octet CRC de même valeur. Après correction : 137/137.

Groupe étendu : **151/151 en Debug et 151/151 en Release**, le 3 novembre 2026. Couverture ajoutée : quatre combinaisons FM/MFM et DMA/PIO en lecture/écriture, Write Deleted, TC et zéro de remplissage, CRC émis vérifié indépendamment, CHRN/CRC erronés, DTL, SK, scans et STP, Read Track avec CRC erronés et ordre enregistré, MT/change de face, WP/READY, formatage préservant N fourni par le CPU, interruption de porte, RESET depuis le callback WE, différences A/B sur OR et maintien DRQ, acquittement DACK sans transfert. Les réinitialisations déclenchées par les callbacks ne doivent pas être écrasées par la fin de commande en cours.

Ces résultats valident ce groupe, pas la clôture du composant. Restent notamment les sorties multiplexées de commande des lecteurs et leurs chronogrammes, PS0/PS1, les extensions propres au 72065B, la matrice finale de cas limites, la preuve invitée et les mesures. Aucun benchmark final, build livré ou commit de clôture µPD765 n'est annoncé.

La comparaison constructeur CMOS, page 5-54, impose 255 impulsions de Recalibrate au 72065B, contre 77 au 765A/B. Le constructeur du cœur sélectionne maintenant cette limite. Six cas supplémentaires vérifient l'arrivée réelle sur TRK0 après 100 pas et l'arrêt à la limite lorsque TRK0 reste bas, pour les trois variantes : **157/157 en Debug**. Le dernier groupe Release reste celui des 151 cas précédents, jusqu'au prochain passage regroupé.

Les sorties MFM, SIDE et US reviennent à zéro au RESET. MFM est maintenant une bascule indépendante du registre de commande : Sense/Version ne changent pas la densité sélectionnée. SYNC active le séparateur externe pendant les recherches ID/DATA ; LCT indique les cylindres au-delà de 42 en lecture/écriture. HDLD est affirmé au début de HLT, la réception reste inactive jusqu'au terme de HLT, puis HDLD reste affirmé jusqu'au terme de HUT. Les tests vérifient les frontières HLT=16 000 et HUT=128 000 CLK à 8 MHz pour les paramètres Specify employés.

Dernier passage regroupé : **165/165 en Debug et 165/165 en Release**, zéro échec. Cela remplace le dernier total Release de 151 indiqué plus haut. Les chronogrammes multiplexés de Seek/STEP/US et FLTR, PS0/PS1, les commandes auxiliaires CMOS et les inhibitions propres aux variantes restent ouverts ; ces tests ne valent ni clôture, ni preuve invitée, ni livraison de l'application.

Correction issue de la lecture visuelle d'AN08 figures 7/8 : le premier getter SYNC ne couvrait pas ID/DATA et désactivait la recherche ID lors d'une écriture. SYNC reste désormais actif dans ces champs, et les raccordements sont inhibés pendant 12 octets FM / 24 MFM après l'ID et GPL après DATA, comptés sur WCLK externe. Formatage et HLT gardent SYNC bas. Premier passage : 166/168, avec une activation prématurée pendant HLT détectée par deux tests existants ; après correction, **168/168 en Debug**. Les nouveaux contrôles vérifient les limites d'octets dans le flux FM/MFM et la recherche de l'ID avant écriture. La description précédente limitée aux phases de recherche est donc remplacée par ce séquencement.

FLTR est maintenant produit pendant 64 CLK (8 µs à 8 MHz, 16 µs à 4 MHz) avant HDLD/HLT, conformément à la durée nominale NEC 5-8 et à AN08 figures 7 à 9. La sortie et son callback permettent au lecteur externe de réinitialiser sa faute ; une faute persistante produit Equipment Check. RESET depuis chacun des fronts annule la commande sans réactiver HDLD. **174/174 tests Debug**, zéro échec, après cet ajout.

Les déplacements utilisent maintenant un bus de sorties partagé : préparation US/SIDE de 96 CLK, RW-SEEK avant DIR de 56 CLK, DIR avant STEP de 8 CLK, STEP haut 56 CLK, maintien DIR de 192 CLK après STEP bas et maintien US de 120 CLK après RW-SEEK bas. À 8 MHz cela donne 12/7/1 µs, STEP 7 µs, maintien DIR 24 µs et US 15 µs ; les durées doublent à 4 MHz. Ces valeurs numériques respectent les minima et le nominal de STEP de NEC 5-8 ; les états « don't care » restent déterministes dans le modèle.

Quatre commandes Seek/Recalibrate gardent leurs PCN et causes indépendants ; leurs passages sur les broches sont sérialisés. Pour quatre mouvements identiques démarrant ensemble, les premiers STEP sont espacés de 528 CLK ; chaque unité garde ensuite SRT entre ses propres STEP. L'interface expose US, SIDE, RW-SEEK, DIR, STEP et les lignes multiplexées FLTR/STEP et LCT/DIR, avec notification. Les fractions d'horloges propriétaire/contrôleur sont conservées dans les échéances internes.

Premier passage après raccordement : 172/174. Deux tests supposaient encore qu'un prochain événement quelconque terminait forcément une écriture de registre et que deux unités émettaient leur STEP simultanément. Le banc avance désormais la durée complète du transfert de commande et contrôle les pas du bus partagé. Un nouveau test de commande après Seek attendait à tort que le bus soit encore occupé après 384 CLK, alors qu'il est libéré après 368 CLK ; l'attente a été corrigée. Dernier passage : **185/185 Debug**, zéro échec. Un test de fraction de polling utilisait une durée de 100 000 secondes à l'horloge propriétaire de 1 Hz ; sa durée est maintenant bornée à douze périodes nominales (avec un tick propriétaire minimum), en conservant la comparaison lots/pas.

Sense Drive Status suit maintenant AN08 figure 11 : US/SIDE sont sélectionnés, FLT/WP/READY sont prélevés en mode lecture, puis TRK0 et 2SIDE en mode Seek. Les trois prélèvements sont séparés de 10 CLK (1,25 µs à 8 MHz, arrondi numérique au-dessus du minimum préliminaire de 1,2 µs). La commande attend la libération du bus des déplacements, produit son ST3 après le dernier prélèvement et s'annule au RESET. Les trois appels d'entrée du banc sont vérifiés aux CLK 10, 20 et 30 avec les modes correspondants.

Premier passage : 186/188, car le helper de commande attendait encore une réponse après RESET maintenu. Il s'arrête maintenant lorsque le MSR nul indique le reset, et les tests continuent à exiger que la commande et ses sorties restent annulées. Après correction du helper : **188/188 Debug**, zéro échec. Les commandes auxiliaires CMOS, la présélection PS et le multiplexage physique du polling READY restent à terminer.

Le dernier octet non acquitté du 765A conserve maintenant DRQ jusqu'à DACK, même lorsque cette variante ne positionne pas OR sur ce dernier octet. Le résultat demeure distinct des variantes B/72065B ; les tests vérifient également la disparition de DRQ après l'acquittement. Passage regroupé du bloc sorties/DMA : **188/188 en Debug et 188/188 en Release**, zéro échec. Les preuves invitées, le benchmark et le build livré restent à réaliser après les fonctions encore ouvertes.

La frontière LCT est corrigée : NEC 5-5 indique le cylindre 42 **inclus**, et non seulement les cylindres suivants. Les tests couvrent 41/42/43. Le µPD72065B possède désormais le registre auxiliaire A0=0 : 34 sortie de veille, 35 entrée en veille, 36 reset logiciel. Ce décodage provient de la source MAME ; les fiches NEC consultées confirment les fonctions mais ne donnent pas leur table de codes. Les µPD765A/B ignorent ce registre.

Le modèle numérique respecte le maintien de 32 CLK à l'entrée et les 16 CLK de reprise de NEC 5-49. Pendant la veille, les registres, échéances et niveaux d'interruption sont conservés ; les horloges internes et prélèvements des entrées s'arrêtent. La reprise conserve le reliquat du polling. Le reset matériel ou logiciel annule la commande et réarme le polling de sortie de reset. Les accès DATA sont bloqués pendant la veille et sa reprise ; les commandes auxiliaires restent accessibles. La fiche ne détaille pas la micro-séquence d'une mise en veille au milieu d'un transfert : cette conservation constitue le modèle nominal retenu, pas une mesure du silicium.

Passage après ce bloc : **198/198 tests Debug**, zéro échec. Les dix cas ajoutés couvrent les durées à 4/8 MHz, le reliquat du polling, l'absence de prélèvement READY pendant la veille, le strobe de bus, les variantes sans registre auxiliaire et les deux resets. Le dernier résultat Release reste 188/188 avant ce bloc.

L'inhibition après INDEX suit la comparaison NEC 5-54 : 4 800 CLK pour le 765A/B (1,2 ms à 4 MHz), 800 CLK pour le 72065B (0,2 ms à 4 MHz). Elle empêche une nouvelle recherche d'ID de reconnaître le flux trop tôt ; elle ne coupe pas un champ DATA déjà engagé ni le formatage. RESET l'annule, la veille conserve son reliquat et les échéances sont exprimées en CLK natifs. Le banc peut alimenter une piste sans attendre les échéances pour exercer explicitement le cas interdit. **205/205 tests Debug**, zéro échec ; le groupe inclut les frontières, 4/8 MHz, Read Track et le rejet du premier ID reçu dans la fenêtre.

Le polling READY sélectionne maintenant réellement US0/US1 : chaque entrée est lue après sélection de son unité, en mode lecture. Les quatre prélèvements ne sont plus réalisés simultanément sans changement des sorties. La réponse après sélection utilise 4 CLK pour le 765A/B et 20 CLK pour le 72065B, d'après NEC 5-54 (0,5/2,5 µs à 8 MHz, 1/5 µs à 4 MHz). Sense Drive Status respecte aussi le délai plus long du CMOS.

Le placement numérique nominal retenu regroupe les quatre sélections en fin de période de 8 192 CLK : les prélèvements A/B ont lieu aux CLK 8 180, 8 184, 8 188 et 8 192 ; ceux du CMOS aux CLK 8 132, 8 152, 8 172 et 8 192. NEC AN08 p. 5 décrit le balayage continu des lignes US entre instructions, mais ne donne pas son microchronogramme détaillé. Ces placements ne sont donc pas présentés comme des mesures du silicium. Seek et Sense ont priorité sur ce bus partagé ; un passage occupé diffère le balayage sans modifier la période du compteur.

Le premier octet d'une commande suspend ce balayage ; il reprend entre commandes, après consommation complète des résultats. Une sortie de RESET interrompue conserve séparément les unités déjà signalées et les autres : reprise sans perte ni duplication de cause READY. La sélection et le prélèvement s'annulent si un callback réinitialise la puce. Les tests conservent également les comparaisons par lots/par cycles et les fractions d'horloges propriétaire.

Premier passage : **210/211 Debug**, avec une ancienne attente de bus encore fondée sur un événement simultané au CLK 8 192. Après adaptation et ajout d'un contrôle d'interruption du balayage de sortie RESET : **211/212**, le nouveau cas révélant une reprise différée jusqu'à la période suivante. Le balayage interrompu reprend désormais dès la fin de commande et conserve le masque des causes déjà produites. Dernier passage regroupé : **212/212 Debug et 212/212 Release**, zéro échec.

Restent avant clôture : présélection PS0/PS1 et ses limites documentaires, revue finale de couverture des variantes, preuve exécutée par un CPU invité, mesures et livraison Debug avec tous les modules. Aucun de ces résultats unitaires n'est une capture invitée ni une annonce de puce terminée.

PS0/PS1 sont désormais exposés avec une valeur typée et une notification horodatée. La table électrique NEC 5-10 donne PS0=1 pour l'avance, PS1=1 pour le retard, les deux bas pour normal ; les deux hauts ne sont jamais produits. WDATA conserve ses fronts non précompensés : l'amplitude du décalage appartient au circuit extérieur, comme décrit par AN08 et [AN10, figure 11](https://bitsavers.org/components/nec/_appNotes/AN10_Considerations_for_Interfacing_NEC765_to_CDC_9404_and_9406_198008.pdf).

La table interne des motifs NEC n'est publiée dans aucune de ces références. Le modèle nominal MFM retenu compense une asymétrie autour de deux cellules : avance si l'impulsion précédente est à deux cellules et la suivante plus loin, retard dans le cas inverse ; FM, espacement symétrique ou voisin inconnu restent normaux. Cette règle est une approximation documentée, pas une table NEC vérifiée sur silicium. Les marques à horloges manquantes restent dans l'historique du flux.

L'anticipation lit au maximum quatre cellules du mot suivant disponible, sans acquittement hôte, demande anticipée, changement du séquenceur ni modification du CRC. Aux limites DATA/CRC, une copie du CRC prédit uniquement les derniers bits du mot courant ; le registre réel ne change que sur les fronts WCLK. Aucun octet n'est préchargé prématurément et aucune valeur n'est inventée si le prochain octet hôte manque. Les callbacks PS peuvent réinitialiser le canal sans laisser émettre l'impulsion annulée.

## Mesures et optimisation

Le CRC octet utilise maintenant le repli XOR équivalent au polynôme CCITT, sans table ni boucle de huit bits. Les 65 536 états avec octet nul et les 256 octets avec état nul sont confrontés à la récurrence série ; la linéarité sur GF(2) couvre leur combinaison. Le chemin sans événement de la section lecteur avance directement son compteur natif, sans prélèvement ni sortie fictifs. Les broches de statut d'un même instant sont prélevées ensemble ; RESET depuis ce callback annule l'avance en cours. **231/231 tests Debug** après ces changements. Les trois programmes invités repassent avec exactement les mêmes cycles, compteurs et verdicts ; avec le contrôle média et le banc de performances, **5/5 contrôles locaux Debug**.

Les premières mesures sous le runner local avec JIT progressif présentent une dispersion Release importante (lecture 15..104 ms), impropre à quantifier le gain.

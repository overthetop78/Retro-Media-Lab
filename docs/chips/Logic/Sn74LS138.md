# SN74LS138 — décodeur/démultiplexeur 3 vers 8

## Sources et fonctions

[TI SDLS014](https://www.ti.com/lit/ds/symlink/sn74ls138.pdf), décembre 1972, révision mars 1988. PDF, extraction et rendus sous `artifacts/.tmp-archives/chips/Logic/TexasInstruments/SN74xx/SN74LS138/`. Le texte extrait ne contient pas les tableaux scannés ; pages 1–4 inspectées sur les rendus.

Page 1–2 : trois sélections A (poids 1), B (2), C (4). Validation lorsque G1=haut, /G2A=bas et /G2B=bas. Une seule sortie /Y0…/Y7 basse à l'adresse CBA sélectionnée ; les sept autres sont hautes. Une validation désactivée impose les huit sorties hautes, quelle que soit l'adresse. Une entrée de validation peut recevoir les données d'un démultiplexeur ; les autres validations et l'adresse conservent leur rôle. Les trois validations et les huit sorties doivent donc être réalisées, pas seulement la sélection utilisée par la carte.

Broches du boîtier 16 : A1, B2, C3, /G2A4, /G2B5, G1 6, /Y7 7, GND8, /Y6 9, /Y5 10, /Y4 11, /Y3 12, /Y2 13, /Y1 14, /Y0 15, VCC16. Sorties TTL pilotées (page 3), pas collecteurs ouverts. Aucun reset, CLK, oscillateur, registre ou interruption.

Diagramme page 2 : le trajet d'une sélection vers une sortie dont le bit correspondant vaut 0 traverse deux niveaux ; vers une sortie dont ce bit vaut 1, trois niveaux. G1 traverse son inverseur puis la logique de validation et le NAND final (trois niveaux) ; /G2A-/G2B empruntent le trajet à deux niveaux. La distinction est conservée même lors de la désélection d'une sortie. Une transition A de 0 vers 1 peut par exemple libérer /Y0 après 11 ns et sélectionner /Y1 après 20 ns : ne pas imposer une commutation instantanée ou simultanée de ces sorties.

Les valeurs caractérisent un modèle numérique à cette charge ; elles ne constituent pas une mesure de chaque porte interne ni une caractérisation garantie de tous les glitches d'entrées multiples ou impulsions très brèves. Ne pas inventer un délai individuel d'inverseur en divisant arbitrairement le délai total. Les entrées d'un même front logiciel sont résolues ensemble : un terme connu bloquant suffit à désélectionner (premier trajet bloquant), tous les termes doivent correspondre pour sélectionner (dernier trajet requis). Une entrée changée qui reste conforme à la sélection ne doit pas imposer son délai à une désélection causée ailleurs. Une cible indéterminée utilise conservativement le plus long délai de ses deux directions ; ce profil de connaissance ne prétend pas déterminer une forme analogique non chiffrée par la fiche. Les changements de sortie issus de trajets distincts restent datés séparément.

## État et événements

Les six entrées mémorisent séparément niveau et connaissance ; une entrée indéterminée n'est pas assimilée à une broche flottante haute. Les sorties incompatibles avec les bits d'adresse connus restent hautes, même si une autre sélection est inconnue. Une validation connue inactive rend toutes les sorties connues hautes, même si les autres entrées sont inconnues. Les autres sorties ne deviennent déterminées basses que lorsque leur sélection et les validations sont établies.

Le composant conserve ses huit propagations, cibles et temps locaux, sans lire un fournisseur ni un autre composant en boucle. À une date commune, toutes les réponses se résolvent avant notification. Les callbacks peuvent modifier les entrées et les destinataires ; aucune réentrance ne déplace le temps pendant la publication. Le calcul s'effectue uniquement aux entrées modifiées et aux échéances. Les dates/niveaux de sortie ne sont pas des états d'initialisation garantis à la mise sous tension.
